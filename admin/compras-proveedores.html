Leyenda: estados y errores frecuentes

Estados

  • Recibido: el mensaje entró, aún no se interpretó por completo.
  • Interpretado: ya se leyó el contenido con la IA.
  • Revisar: conviene mirar el mensaje o corregir datos.
  • Falló: no se pudo seguir el flujo.
  • Sin pedido: no había ítems de compra en el texto/foto/audio.

Errores (código → significado)

  • empty_hint: no se detectó nombre de proveedor en el mensaje.
  • not_found: el proveedor no coincide con ninguno cargado (revisar alias en admin).
  • compute_lines_failed: el proveedor existe pero las reglas/unidades no permiten calcular el pedido (revisar JSON de reglas y unidades del mensaje).

Actualizar reglas de un proveedor

Se crea una nueva versión de reglas y queda activa. Se incluyen automáticamente par, tarea y docena (y bulto si lo usás) para que los mensajes de Telegram no fallen por unidad.

Valores comerciales

Opción avanzada: pegar JSON completo

Solo si necesitás campos que este formulario no muestra (por ejemplo unidades personalizadas). Reemplaza todo el objeto de reglas.
